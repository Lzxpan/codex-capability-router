# 1.0.0 release validation

This stable release changes the package version and public documentation. Router
runtime behavior remains the beta.10 production implementation. Protocol IDs with
`v0.2` in their names remain unchanged; they are schema contracts, not the package
release version. Historical beta releases and validation records are retained.

## Reproduce the checks

Run from the repository root with Python 3.11+ and Git:

```bash
python -m unittest tests.test_foundation tests.test_v1_release -v
python -m unittest discover -s tests -q
python -m compileall -q codex_capability_router tests
python scripts/verify_release.py
git diff --check
```

Use `python3` where required by the platform. The release script checks current
versions, ZH/EN core-fact tokens and identical installation commands, local README
links, referenced PNG assets, SVG/XML, strict UTF-8, U+FFFD and credential/private-path
patterns. It checks tracked public files plus explicit release additions, not
unrelated untracked plans or the local capability inventory. Pattern scans are
bounded checks, not a guarantee that every possible secret can be recognized.

## Separate acceptance gates

| Gate | Required evidence |
| --- | --- |
| Runtime scope | Only `__version__` changes inside `codex_capability_router`; compare all other runtime bytes to beta.10. |
| Focused and full tests | Fresh zero-exit outputs after the final content mutation. |
| Documentation | Link, asset, architecture, version and bilingual fact checks, plus semantic review. |
| Visual QA | Inspect every final image for intact framing, original consistent characters, no watermark or private information, then inspect README rendering at GitHub-like desktop and mobile widths. |
| Fresh clone | Clone the base repository into a new directory, overlay only release candidate files and run the same checks before committing. After tag push, clone `v1.0.0` and repeat before creating the release. |
| Release scope | Explicit file allowlist; exclude existing untracked plans and local routing/QA artifacts. |
| Publication | Non-force main push, new annotated `v1.0.0`, stable GitHub release with draft and prerelease both false. |

Observed command results and final identifiers belong in the GitHub release and
task completion report. This document specifies the checks; it does not claim a
check passed merely because a command is listed.

## Evidence boundaries

The real Skill test uses one fresh route from the installed beta.10 production
Router. Host-authored batch dispositions are separate from staged digests. Missing
responses and `needs_detail` remain PARTIAL. A FINALIZED Receipt is not proof of
complete semantic coverage, correct selection, application or execution success.

The final selected Provider list is authoritative. The beta.10 preparation-era
`provider_selected_total` metric can remain zero even when the finalized
`selected_count` and selected Provider list are nonzero. This release preserves
runtime behavior and does not fix that existing diagnostic inconsistency.

No automatic Host integration across every environment, complete global discovery,
persistent preference learning, physical firmware acceptance, or universal Provider
readiness is certified. Source and static checks do not establish those claims.

## Public-data purpose and retention map

Only metadata and synthetic examples are needed for this release audit.

| Fields | Purpose | Store | Retention / deletion |
| --- | --- | --- | --- |
| Version, public contract labels and examples | Installation and correct interpretation | Git repository and GitHub release | Public version history; later corrective commits, not silent history rewrites. |
| Original character descriptions and generated artwork | Explain the workflow | `docs/assets/v1.0.0` and image-generation service | Repository history; generated originals follow Host/provider retention. Router does not manage service deletion. |
| Canonical capability IDs, fingerprints and dispositions | Evaluate the one task route | Caller-owned local task evidence only | Caller/session-owned; remove the task evidence directory when no longer needed. Not committed or attached to the release. |
| Check names, outcomes and public commit/tag identifiers | Substantiate publication | Task report and GitHub release | Public release record; corrections are explicit. |
| Credentials, private arguments and private absolute paths | No public release purpose | Not permitted in release artifacts | Excluded at collection and checked before publication. |

The library does not add a persistent inventory or preference store. The Host and
external image service have their own storage policies; this release does not
claim to audit or control those policies.
