# Codex Capability Router v1.0.0

Stable release. Package version: `1.0.0`; annotated tag: `v1.0.0`.

## What changes

- Promote the package from `v0.2.0-beta.10` to `v1.0.0` without changing Router runtime behavior.
- Make `README.md` the Traditional Chinese homepage and retain a functionally equivalent `README.en.md`; `README.zh-TW.md` mirrors the Chinese homepage for existing links.
- Explain the workflow with an original animal-cast hero, an eight-panel continuous tutorial, a four-panel principles comic, and version-controlled SVG/Mermaid architecture.
- Add portable pinned-version installation commands and focused documentation/release checks.

## What stays true

The Host LLM owns TaskAnalysis and semantic Skill/Provider decisions. Python owns
deterministic discovery, validation, source freshness, handoff and Receipt evidence.
Staged digests are not semantic consideration; incomplete Host decisions remain
PARTIAL. FINALIZED is not execution success. Providers are `app`, `mcp`,
`builtin_tool` or `host_tool`; Plugin is provenance, not a Provider.

No fixed top-k, fixed Skill maximum, or automatic overlap/redundancy exclusion is
introduced. SPARSE/OPAQUE candidates may remain. Targeted Skill freshness recovery
allows at most one refresh, with the existing revalidation and rejection statuses.
Cache lifetime remains caller/session-owned. Persistent preference learning and
automatic integration in every Host environment are not claimed.

The existing beta.10 Provider count diagnostic inconsistency remains: use the
final selected Provider list and `selected_count`, not the preparation-era
`provider_selected_total`, to inspect final selection. No runtime fix is included.

## Validation and publication

The [validation guide](../validation/v1.0.0-validation.md) defines the reproducible
checks. Publication requires fresh focused/full tests, compileall, static and
privacy checks, README links/assets, SVG parsing, ZH/EN parity, actual visual QA,
fresh-clone verification and release-scope review. Observed results are appended
to the GitHub release only after these gates pass.

GitHub publication is stable: `prerelease = false`, `draft = false`. Existing beta
tags are preserved. No PyPI publication, hardware test, universal Host integration
or new Provider readiness certification is part of this release.

## Recovery

To return to the previous runtime/documentation, use the preserved
`v0.2.0-beta.10` tag in a separate checkout. No data migration is required. If a
public correction is needed, make a follow-up corrective commit or release;
do not move an existing beta or stable tag.
